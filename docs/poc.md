## 公開前に確かめたこと（2026-11-16）

- **衝突したときに進捗シンクへ届くもの**：同じ名前がある先へコピーして上書き・統合すると、`PostCopyItem` は上書き先・統合先の既存の項目を `S_OK` で返す。フォルダは、フォルダ自身に続けて中の項目も 1 件ずつ届く。同じドライブでの移動は `COPYENGINE_S_DONT_PROCESS_CHILDREN`（0x270008）、統合したフォルダは `COPYENGINE_S_NOT_HANDLED`（0x270003）。どれも成功コードなので、結果コードでは「新しく作られた項目」と見分けられない。そこで、操作の前に落とす先に同じ名前があった項目は、元に戻す記録から外す（`fileops.rs` の `names_taken`）。中の項目は、親が記録に入るので外す（`is_inside`）
- **フォルダの監視が止まるとき**：notify（`ReadDirectoryChangesW`）は、監視中のフォルダが消えたり共有が切れたりすると、何も知らせずにそのフォルダの監視をやめる。そこで 3 秒ごとにフォルダがあるかを確かめ、戻ったら張り直す（`watcher.rs` の `check_alive`）
- **オンラインのみのファイル**：Dropbox の「オンラインのみ」の画像で、`IShellItemImageFactory::GetImage` のアイコン（`SIIGBF_ICONONLY`）と縮小版（256px）を取った。どちらも画像が返り、ファイルは「オンラインのみ」のままだった（`FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` が付いたまま）。再現：ファイルのパスを書いたテキストファイルを `VESTA_TEST_ONLINE_ONLY` に指定して `cargo test online_only_file_stays -- --ignored --nocapture`。OneDrive では確かめていない
- **260 文字を超えるパス**（327 文字のフォルダ。`cargo test long_paths_probe -- --ignored --nocapture`）：一覧、コピー、名前の変更とその取り消しはできた。シェルは作った項目のパスを短い名前（`とても~1`）で返す。ごみ箱へ送る操作は「指定されたファイルが見つかりません」で失敗し、新規作成は中止になった。マニフェストの `longPathAware` は付けていない
- **並び順**：`Intl.Collator("ja", { numeric: true })` は、全角の数字も数として比べる

## 当初の想定から変えたこと

- **外へのドラッグ**：`drag` crate はやめた。効果をコピーか移動の一方しか指定できず、古い `windows` 0.58 も一緒に入るため。代わりに `SHDoDragDrop` で COPY | MOVE | LINK を渡し、ドロップ先に決めさせる。
- **ごみ箱から元に戻す**：IFileOperation の PostDeleteItem で受け取る項目は、ごみ箱の中の `$R...` ファイルそのもので、その右クリックメニューに「元に戻す」がない。そこで `$R...` のパスを記録しておき、元に戻すときにごみ箱を列挙して一致する項目を探し、その「元に戻す」（undelete）を実行する。見つからなければ、`$R...` ファイルを元のパスへ移す（元の場所に同じ名前の項目があれば、上書きせずに止める）。
- **ビルド出力**：リポジトリを Dropbox などの同期フォルダに置くと、`target/` を同期しようとしてビルドが失敗する。`src-tauri/.cargo/config.toml`（git 管理外）で出力先を同期の外にする（README「開発」）。
